Images can help a business website explain its services, demonstrate products and give visitors confidence in what the organisation offers.

They can also create additional opportunities for discovery through [Google Images](/articles/tag/google-images) and other visual search experiences.

However, uploading photographs to a website is not the same as optimising them for search.

A photograph with an automatically generated filename, no useful alternative text and little connection to the surrounding page gives search engines limited context about what it represents.

The same image may also be unnecessarily large, slowing down the page for visitors using mobile data.

[Image SEO](/articles/tag/image-seo) brings together several disciplines: [search visibility](/articles/tag/search-visibility), [accessibility](/articles/tag/accessibility), content relevance and technical performance.

Google's current [image SEO best-practice documentation](https://developers.google.com/search/docs/appearance/google-images) explains how website owners can help Google discover, understand and index their images.

For small and growing South African businesses, improving image SEO can make existing [website content](/articles/tag/website-content) more useful without requiring a completely new marketing strategy.

## Why image SEO matters

Google offers several ways for people to discover visual content, including Google Images, images associated with ordinary search results and Google Discover.

These experiences can help users find:

- Products.
- Business locations.
- Service examples.
- Portfolio work.
- Educational diagrams.
- Instructional photographs.
- Informational content.

A business that sells furniture, for example, should not rely entirely on text to explain its products. Clear product photographs can help visitors understand the design, finish, size and appearance of an item.

A construction business may use project photographs to demonstrate the type of work it has completed.

A professional services firm may use original diagrams to explain complicated processes.

Images can therefore support both the visitor's decision-making process and the wider content of a website.

However, appearing in Google Images is not guaranteed. Optimisation improves discoverability and context; it does not promise a particular ranking or volume of traffic.

## 1. Use descriptive image filenames

One of the easiest improvements is to replace generic image filenames with meaningful descriptions.

Consider these examples:

**Generic filename**

```text
    IMG_20261102_0045.jpg
```

**Descriptive filename**

```text
    wooden-office-desk-custom-cabinet.jpg
```

The second filename gives a clearer indication of what the image contains.

Google explains that filenames provide lightweight clues about image subject matter. Its documentation recommends short, descriptive filenames rather than generic identifiers such as `image1.jpg` or `pic.gif`.

A useful filename should:

- Describe the actual image.
- Use a small number of relevant words.
- Separate words with hyphens.
- Avoid unnecessary dates and identifiers.
- Avoid repeating the same keyword excessively.
- Remain understandable to someone viewing the filename.

Do not turn the filename into a list of search phrases.

For example:

```text
    cheap-web-design-websites-web-design-south-africa-websites.jpg
```

is not a useful description.

A more natural filename would be:

```text
    small-business-website-homepage-design.jpg
```

The purpose is to identify the image, not to force additional keywords into its address.

## 2. Write useful alternative text

Alternative text, usually called alt text, describes an image when it cannot be seen or when assistive technology needs to communicate its content.

It is important for accessibility and can also help search engines understand what an image represents.

Consider a photograph showing a carpenter fitting a wooden kitchen cabinet.

A useful alt description could be:

```text
    Carpenter fitting a wooden kitchen cabinet in a residential kitchen.
```

This describes the actual image in a natural way.

Compare it with:

```text
    Kitchen cupboards carpenter cabinets kitchen renovations kitchen design cheap carpenter near me.
```

The second example is keyword stuffing rather than useful image description.

Google's guidance specifically warns against filling alt attributes with keywords because this creates a poor experience and may be treated as spam.

### Alt text should describe the image's purpose

The right description depends on why the image appears on the page.

If a photograph demonstrates a completed project, describe what is visible.

If an image contains a chart, explain the information that the chart communicates. Where the chart contains detailed data, provide an equivalent explanation in the surrounding page content.

If an image is used as a link, the alternative text should help communicate the destination or purpose of the link.

If an image is purely decorative, an empty alt attribute may be appropriate:

```text
    alt=""
```

This prevents assistive technology from announcing decorative content that adds no meaningful information.

### Do not repeat the surrounding heading

Alt text should add useful context rather than repeat the page title word for word.

If the heading already explains that a page is about website development, an image of a laptop showing a website preview could have a more specific description.

The objective is to describe what the visitor would miss if the image were unavailable.

## 3. Place images near relevant content

An image should appear in a section that explains or discusses the subject it represents.

Imagine an article about kitchen renovations that includes:

- A photograph of a completed kitchen.
- A diagram showing cabinet measurements.
- An image explaining countertop materials.

Each image should appear near the text that discusses it.

This creates a clearer relationship between the image and the page's subject.

Google's documentation explains that the content of the page, captions, image titles and surrounding text can help its systems understand an image.

Avoid placing unrelated stock photographs throughout a page simply to make it appear more visually interesting.

A relevant image is more useful to the visitor and provides better context for search engines.

## 4. Use original photographs where possible

Original images can help a business communicate its actual products, people, services and work.

For example:

- A furniture manufacturer can photograph its own products.
- A restaurant can show its actual dishes and dining environment.
- A contractor can display completed projects with the customer's permission.
- A consultant can create original diagrams explaining a process.
- A training provider can show genuine training environments.

Stock photography may still be useful for general illustrations, but it should not create a misleading impression about the business.

If a business serves customers in [Maboloka](/locations/maboloka), [Soshanguve](/locations/soshanguve), [Centurion](/locations/centurion) or surrounding areas, photographs should accurately represent the business, its work or its premises.

Do not use a photograph of a building, office or project in a particular location if the business has no legitimate connection to it.

Do not present generated images as photographs of completed customer projects.

Authentic visual evidence can help customers understand what the business actually provides.

## 5. Optimise image dimensions and file sizes

A photograph may look perfectly reasonable on a desktop screen but be unnecessarily large for a mobile device.

A common mistake is uploading a high-resolution photograph directly from a camera and displaying the original file at a much smaller size.

This can force mobile visitors to download more data than the page requires.

Google's image documentation recommends applying modern image optimisation and responsive image techniques because images can contribute significantly to overall page size.

The [web.dev image performance guide](https://web.dev/learn/performance/image-performance) explains that images are often among the heaviest resources on a website and that serving appropriately sized files can reduce the number of bytes transferred.

Practical improvements include:

- Resize photographs to suit their display dimensions.
- Compress images while maintaining acceptable visual quality.
- Use modern formats such as WebP or AVIF where appropriate.
- Avoid uploading several unnecessary versions of the same photograph.
- Generate smaller image variants for narrower screens.
- Preserve a suitable fallback for browsers that do not support a selected format.

There is no universal file-size target that works for every image.

A small thumbnail and a full-width project photograph have different requirements.

The correct balance is to deliver enough detail for the intended use without making visitors download unnecessary data.

## 6. Use responsive images

Responsive images allow the browser to select an appropriate image file for the available screen space and device characteristics.

For example, a desktop screen may display a large photograph while a mobile device only needs a smaller version.

Instead of forcing every visitor to download the largest file, developers can provide multiple versions using the HTML `srcset` and `sizes` attributes.

A simplified example is:

```text
    <img
      src="project-800.jpg"
      srcset="project-400.jpg 400w, project-800.jpg 800w, project-1200.jpg 1200w"
      sizes="(max-width: 600px) 100vw, 800px"
      width="1200"
      height="800"
      alt="Completed wooden kitchen installation"
    />
```

The browser uses the available information to choose an appropriate file.

The [MDN responsive images guide](https://developer.mozilla.org/en-US/docs/Web/HTML/Guides/Responsive_images) explains how `srcset`, `sizes` and the `picture` element support different image sizes and display requirements.

Responsive image implementation is particularly useful for [websites](/articles/tag/websites) with large product catalogues, image galleries and project portfolios.

## 7. Use standard HTML image elements for important content

There is a technical distinction between an image embedded in HTML and an image used purely as a CSS background.

Google explains that its systems can discover images through the `src` attribute of an HTML `img` element.

Google does not index CSS background images in the same way.

For important content images, use an appropriate HTML image element.

For example:

```text
    <img
      src="/images/completed-office-installation.jpg"
      alt="Completed office furniture installation"
      width="1200"
      height="800"
    />
```

CSS background images are still useful for decorative elements, visual treatments and backgrounds.

They should not be the only way important visual information is made available.

This distinction is especially important when the image itself communicates something meaningful about a product, service or article.

## 8. Add appropriate image dimensions

Images should have suitable width and height attributes where practical.

These values help the browser reserve space for the image before the file has finished loading.

Without reserved space, page elements may move when the image appears.

This can create an unstable experience, especially when several images load as someone scrolls through a long article or gallery.

For example:

```text
    <img
      src="/images/business-team.jpg"
      alt="Small business team meeting around a desk"
      width="1200"
      height="800"
      loading="lazy"
    />
```

The dimensions should reflect the actual image's aspect ratio.

Do not insert arbitrary dimensions simply to make the code appear complete.

## 9. Use lazy loading carefully

Lazy loading delays the retrieval of images that are not immediately needed.

It can reduce unnecessary network usage when a page contains many images below the initial viewport.

For example, an article with ten photographs does not necessarily need to download all ten before the visitor can begin reading.

An image further down the page can use:

```text
    loading="lazy"
```

However, avoid applying lazy loading indiscriminately.

The main hero image or another important image visible immediately when the page opens should normally be loaded promptly.

Delaying the main visible image can make the page appear slower.

A sensible strategy is to load important above-the-fold images eagerly and defer non-critical images lower down the page.

## 10. Create an image sitemap when useful

An XML image sitemap can provide search engines with additional information about images on a website.

It can be particularly useful when a website has a large number of images or when important image URLs are not easily discovered through ordinary crawling.

Google explains that image sitemaps can help it discover images that might otherwise be difficult to find.

An image sitemap is not compulsory for every small website.

Before creating one, confirm that:

- Important images are already accessible.
- The image URLs return successful responses.
- The pages containing those images can be crawled.
- The sitemap references the correct image locations.
- CDN-hosted images are configured appropriately.
- The sitemap does not contain obsolete or broken files.

A sitemap is a discovery aid, not a guarantee that every submitted image will be indexed.

## 11. Provide appropriate image metadata

Images used in search previews and social sharing should be selected carefully.

Google's documentation explains that website owners can provide preferred image information through metadata such as:

- Schema.org `primaryImageOfPage`.
- The `image` property associated with a main entity.
- The Open Graph `og:image` property.

For an article, the selected image should represent the article rather than simply repeat the website logo.

Use a suitable image with enough resolution for the intended preview.

Avoid extremely narrow or unusually wide images when choosing a primary image for search or sharing metadata.

Structured data can make content eligible for certain search features, but it does not guarantee that Google will display a particular image or rich result.

## 12. Make image optimisation part of the publishing process

Image SEO should not be a task that happens only when a website receives an audit.

It should form part of the content-publishing workflow.

Before publishing a new article, product or service page, check the images being added.

| Check | What to verify |
| --- | --- |
| Filename | Descriptive and understandable |
| Alt text | Accurate and useful |
| Relevance | Image supports the surrounding content |
| Dimensions | Appropriate for the display size |
| File size | Compressed without unacceptable quality loss |
| Format | Suitable for the image and browser support |
| Responsive behaviour | Smaller files available where appropriate |
| Loading | Important images are not unnecessarily delayed |
| Metadata | Preferred image information is accurate |
| Licensing | Business has permission to use the image |

A consistent process helps prevent image quality, accessibility and performance problems from accumulating as the website grows.

## How to measure image SEO performance

Image optimisation should be evaluated using more than the number of photographs uploaded.

Useful checks include:

**Google Search Console**

Review the Search performance report and select the Image search type where available.

Examine impressions, clicks, click-through rate and the queries associated with image discovery.

Look for pages and images that receive visibility but attract limited engagement.

**Page performance**

Use PageSpeed Insights and browser developer tools to identify oversized images, unnecessary downloads and image-loading issues.

**Accessibility**

Review whether meaningful images have useful alternative text and whether decorative images are handled appropriately.

**Business outcomes**

If image traffic reaches product or service pages, assess whether visitors proceed to enquiries, purchases or other meaningful actions.

A photograph that attracts search traffic but does not help visitors understand the business may not be contributing much commercial value.

## Frequently asked questions

### Does image SEO improve Google rankings?

Image SEO helps search engines discover and understand visual content. It can create opportunities for image search visibility, but it does not guarantee higher rankings for the page or image.

### Should every image have alt text?

Meaningful content images should have appropriate alternative text. Decorative images can use an empty alt attribute so that assistive technology does not announce unnecessary information.

### Are image filenames important?

Descriptive filenames provide additional context about an image. They are useful, but they are only one of several signals that search engines can consider.

### Should I use WebP or AVIF?

Both are modern image formats that can reduce file sizes compared with some traditional formats. Choose a format that suits the image, browser support and delivery requirements, and provide appropriate fallbacks where necessary.

### Do I need an image sitemap?

Not every website needs a separate image sitemap. It can be helpful for larger sites or where important images are difficult for search engines to discover.

### Can I use stock photographs?

Yes, where the business has the appropriate licence. However, stock photographs should not misrepresent the business, its staff, premises or completed work.

## Conclusion

Images are part of the content and technical structure of a website.

They help visitors understand products and services, provide visual evidence and create additional opportunities for discovery through search.

The most useful image SEO improvements are straightforward: use descriptive filenames, write meaningful alt text, place images in relevant content, serve appropriately sized files and ensure important images are accessible to search engines.

These practices also improve accessibility and can reduce unnecessary data usage.

For a growing business, image optimisation should become a normal part of publishing rather than an afterthought.
