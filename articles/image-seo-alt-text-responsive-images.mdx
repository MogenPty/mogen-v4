Images can explain a service, demonstrate a product, establish trust and make a website easier to understand. They can also help search engines interpret the page and, where relevant, discover images through Google Images and other visual search experiences.

Yet image optimisation is often reduced to one task: adding a keyword to an image's alternative text. That overlooks several important factors, including the surrounding page content, image [accessibility](/articles/tag/accessibility), technical discoverability, file size and the way images are delivered to different devices.

For South African small businesses, these details matter because photographs, diagrams and product images often help customers decide whether a service is relevant to them. A useful image should work for the visitor first, while being implemented in a way that search engines can understand.

This guide explains how to approach [image SEO](/articles/tag/image-seo) without keyword stuffing or unnecessary technical complexity.

## What is image SEO?

Image SEO is the process of making website images accessible, understandable and technically discoverable.

It includes:

- Choosing images that genuinely support the page.
- Writing useful alternative text.
- Using descriptive filenames.
- Providing relevant surrounding text.
- Embedding images in crawlable HTML.
- Delivering appropriately sized images.
- Supporting responsive layouts.
- Making important images discoverable to search engines.

Google's [image SEO best practices](https://developers.google.com/search/docs/appearance/google-images) explain how [websites](/articles/tag/websites) can help Google discover and understand images.

Image optimisation does not guarantee that an image will appear in Google Images, Discover or a standard search result. Search engines determine what to show based on their systems and the relevance of the available content.

## 1. Start with the purpose of each image

Before renaming files or writing alternative text, ask why the image exists.

A photograph of a finished kitchen on a renovation company's website has a different purpose from a decorative background behind a heading. A diagram explaining a technical process has a different purpose from a thumbnail used to link to another article.

The image's role determines how it should be described and implemented.

Consider these categories:

- **Informative images:** communicate useful facts, objects or activities.
- **Functional images:** help visitors operate a link or control.
- **Complex images:** present charts, diagrams or detailed information.
- **Decorative images:** add visual atmosphere without conveying essential information.

Do not use an image merely because a page looks empty. Select visuals that support the message, demonstrate the service or help visitors understand what happens next.

For a business serving customers in [Maboloka](/locations/maboloka), [Soshanguve](/locations/soshanguve), [Centurion](/locations/centurion) or surrounding areas, genuine photographs of relevant work may provide useful context. Use location references only when they accurately describe the image and the business's real work.

Never invent a local project or imply that a photograph depicts a completed job in a particular town when it does not.

## 2. Write useful alternative text

Alternative text, usually called alt text, is an HTML attribute that provides a textual alternative for an image.

It is important for accessibility and can also help search engines understand an image's subject.

A useful description focuses on what the image contributes to the page.

For example:

- Weak: `image1.jpg`
- Weak: `best affordable web development website design SEO Pretoria`
- Better: `Responsive website displayed on a laptop and smartphone`
- Better for a portfolio image: `Completed wooden kitchen renovation with white cabinets and stone worktops`

The best wording depends on the actual image and context.

### Avoid keyword stuffing

Alternative text is not a place to list every service, town and keyword that a business wants to rank for.

A description should be accurate, concise and relevant. If a photograph shows a laptop displaying a website, its alt text should describe that image rather than attempt to promote unrelated services.

Repeating the same keyword-heavy description across every image provides little value to users and may make the page less useful.

### Decorative images need different treatment

A purely decorative image generally should not be given a verbose description that adds no meaningful information. In HTML, an empty alternative-text attribute can allow assistive technology to skip such an image.

Functional images require text that communicates the action or destination. Complex images may need a longer explanation elsewhere on the page.

Review the actual implementation rather than applying the same rule to every image.

## 3. Use descriptive filenames

Filenames can provide useful context, particularly when they accurately describe the image.

Compare:

- `IMG_4938.jpg`
- `web-development-responsive-business-website.jpg`

The second filename is easier for a person managing a media library to understand and may provide additional context to search engines.

Use short, descriptive names and separate words with hyphens. Avoid excessively long filenames, repeated keywords and claims that the image does not support.

Filename optimisation should not become an excuse to rename every existing image without a clear benefit. If an image is already published at a URL, changing the filename changes that URL. Update references carefully and consider appropriate redirects where necessary.

A consistent naming convention also makes it easier for staff to maintain a growing image library.

## 4. Give images meaningful context on the page

Search engines interpret images alongside other information about the page.

The heading, nearby paragraphs, captions and the page's overall subject can all help establish what an image represents.

For example, a page describing a particular service can include a relevant photograph, a concise caption and text explaining what the photograph demonstrates.

Avoid placing unrelated stock images between sections simply to make a page longer. An image should have a clear relationship to the content.

Captions are useful when visitors benefit from knowing what is shown, where the photograph was taken or what a diagram illustrates. They should not repeat the same information unnecessarily.

Context should also be accurate. Do not label a generic stock photograph as a real customer project or use a caption that implies a business has an office in a location where it does not operate.

## 5. Make important images discoverable in HTML

One of Google's specific recommendations is to use standard HTML image elements.

Google can discover images referenced through the `src` attribute of an HTML `img` element. Google states that it does not index CSS images in the same way.

This matters when deciding how to implement a visual.

A decorative background implemented in CSS may be appropriate when the image is purely atmospheric. However, if an image conveys important information or should be discoverable through image search, an HTML image element is generally the more suitable implementation.

Responsive implementations can use the `picture` element or `srcset` to offer different image files for different display conditions. Google recommends providing a fallback image URL through the `src` attribute.

See Google's [image SEO guidance](https://developers.google.com/search/docs/appearance/google-images) for examples and implementation details.

## 6. Optimise file size without sacrificing useful detail

Large image files can increase page weight and make a website slower to load, particularly on mobile devices or slower connections.

Optimisation should balance file size, visual quality and the image's intended display size.

Practical steps include:

- Resize images to dimensions appropriate for their display.
- Use a suitable image format.
- Compress photographs carefully.
- Avoid uploading full-resolution camera images when the page only needs a smaller version.
- Provide responsive variants for different screen sizes.
- Avoid loading unnecessary duplicate images.

Google supports several common image formats, including JPEG, PNG, WebP, SVG and AVIF, subject to the relevant technical requirements.

Photographs often benefit from efficient raster formats, while logos and simple illustrations may be better suited to vector formats where appropriate. The correct choice depends on the image and the website's browser-support requirements.

Do not compress an image so aggressively that product details become difficult to see. The purpose of optimisation is to deliver an appropriate image efficiently, not to reduce every file to the smallest possible size.

## 7. Use responsive images for different devices

A single oversized image is not always appropriate for every screen.

Responsive images allow a browser to select a suitable file for the device and layout. This can reduce unnecessary downloads while maintaining useful visual quality.

A website might use a smaller image for a narrow mobile layout and a larger variant for a wider desktop presentation.

When implementing responsive images, ensure that:

- The available variants represent the same intended image.
- The browser can select a suitable resource.
- A valid fallback image is present.
- The image does not distort or overflow its container.
- Important content is not lost when the layout changes.

Responsive images should be tested on real devices or suitable browser emulation. A technically valid implementation can still produce poor results if its dimensions, crop or layout are inappropriate.

## 8. Decide when an image sitemap is useful

An image sitemap can help search engines discover images that might otherwise be difficult to find.

This can be useful for a large media library, a portfolio with many project photographs or a website where important images are not easily discovered through ordinary internal links.

However, an image sitemap is not a replacement for good page structure. The pages containing important images should still be accessible and crawlable, and the images should be referenced correctly.

Google also recommends submitting a sitemap to help communicate changes to the site. Its [image SEO documentation](https://developers.google.com/search/docs/appearance/google-images) explains image sitemap support, including the use of image URLs hosted on other domains.

Before creating a separate image sitemap, consider whether the website's existing sitemap setup already supports the required discovery. Avoid adding unnecessary infrastructure when a simpler implementation is sufficient.

## 9. Treat image metadata and licensing separately

Some images have licensing or attribution requirements. Others may include metadata identifying the creator, copyright information or permitted usage.

Google provides guidance on [image licence metadata](https://developers.google.com/search/docs/appearance/structured-data/image-license-metadata), explaining how structured data or embedded IPTC metadata can communicate licensing information for eligible Google Images features.

This is distinct from ordinary alt text.

A business should establish where images come from and whether it has permission to use them. Keep licence details or attribution information where required, and do not assume that an image found through a search engine is free to reuse.

If the business uses original photographs, preserve relevant ownership and licensing records. If images come from a supplier, photographer or stock library, follow the applicable terms.

## 10. Measure image SEO without guessing

It is easy to spend time renaming files and rewriting descriptions without checking whether the changes are useful.

Start by identifying the pages and images that matter most. Then review their technical implementation and available performance data.

Useful checks include:

- Whether important pages can be crawled.
- Whether the image URLs load successfully.
- Whether alternative text accurately describes meaningful images.
- Whether image files are unnecessarily large.
- Whether images display correctly on mobile.
- Whether the pages provide relevant content around the images.
- Whether search reporting shows image-related visibility or visits where available.

Do not interpret every change in image impressions as proof that a filename or alt-text adjustment caused the change. [Search performance](/articles/tag/search-performance) is affected by many factors, including the page's relevance, competition and search demand.

A sensible process focuses on accurate implementation and useful content first, then uses data to identify further opportunities.

## A practical image SEO checklist

Use this checklist when publishing new pages or reviewing existing content.

- [ ] Every important image has a clear purpose.
- [ ] Meaningful images have appropriate alternative text.
- [ ] Decorative images do not introduce unnecessary screen-reader content.
- [ ] Filenames are descriptive and accurate.
- [ ] Images support the page's actual subject.
- [ ] Images use suitable HTML implementation.
- [ ] Responsive images include a valid fallback.
- [ ] File sizes are appropriate for their display dimensions.
- [ ] Important image URLs are accessible to crawlers.
- [ ] An image sitemap is considered where useful.
- [ ] Licensing and usage permissions are understood.
- [ ] Image-related performance is reviewed periodically.

## Frequently asked questions

### Does alt text directly guarantee better Google rankings?

No. Alt text helps communicate the purpose or content of an image and supports accessibility. It does not guarantee a particular ranking or appearance in search results.

### Should every image contain the primary keyword?

No. Alternative text and filenames should accurately describe the image. Use relevant wording naturally rather than forcing keywords into every description.

### Are images implemented as CSS backgrounds bad for SEO?

Not necessarily. CSS backgrounds are appropriate for decorative visuals. However, Google states that it does not index CSS images in the same way as images embedded through standard HTML image elements.

### Do I need an image sitemap?

Not every website needs a separate image sitemap. It can help with discovery in suitable cases, but it should complement accessible pages and good image implementation rather than replace them.

## Conclusion

Image SEO combines accessibility, content quality and technical implementation. Descriptive alternative text, meaningful filenames, relevant page context, responsive delivery and crawlable image elements provide a sound foundation.

Focus on the images that genuinely help visitors understand the business and its services. Optimise those images carefully, monitor the results and avoid treating keyword repetition as a substitute for useful content.
